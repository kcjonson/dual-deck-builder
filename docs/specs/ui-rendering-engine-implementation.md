# UI rendering engine: implementation specification

Status: approved for planning, 2026-09-07. No engine code has changed; this document is the spec for the epic that will.
Specification implemented: [docs/ui-rendering-spec/](../ui-rendering-spec/README.md) (rules cited as R3.14 etc.)
Decision record: [docs/AI_TECHNICAL_DECISIONS/ui-rendering-spec-adoption.md](../AI_TECHNICAL_DECISIONS/ui-rendering-spec-adoption.md)
Research and review inputs: [docs/ui-rendering-spec/research/](../ui-rendering-spec/research/README.md), [docs/ui-rendering-spec/review/](../ui-rendering-spec/review/README.md); the implementer review ([04-implementer.md](../ui-rendering-spec/review/04-implementer.md)) carries the file-by-file migration map this document summarises.

## 1. Purpose and scope

Replace the engine under `src/renderer/engine` with an implementation of the layered UI rendering specification, in phases that keep the game playable, so that the UI can then be polished on a foundation that renders in the right order, clips correctly, measures text exactly, lays itself out, and can be verified by a machine. In scope: the rendering backend, draw API and batcher, text, the component tree and input, layout, tokens and theme, the component catalog, developer tooling, and the migration of every existing screen onto them. Out of scope: gameplay features that only become buildable afterwards (map, garage, events, drag targeting with previews); they are tracked in the game feature roadmap epic and cite this work as a blocker.

## 2. Why

The current engine draws one GPU call per shape through a WebGL1 context, batches only text (per colour, flushed on every scissor change, so text always paints above shapes drawn in the same clip scope), ignores `borderRadius`, `opacity`, `fontFamily`, and `zIndex`, scales a 32 px Arial bitmap for every text size, has no layout engine, no theme, no popups, no focus manager, and no way to verify a screen except by eye. Four of the five rendering bugs on the board (DDB-28 doubled card titles, DDB-29 hand overflow, DDB-30 turn banner overlap and off-centre title, DDB-31 deck preview through the cycle button) trace to those gaps; DDB-32 (panel scrolling) and DDB-41 (splash fade, needs opacity) are blocked on them. The audit in [research/04-sibling-engine-audit.md](../ui-rendering-spec/research/04-sibling-engine-audit.md) has the evidence per file and line. Worldsim spent a year solving the same problems; the specification is that work made portable.

## 4. Ground rules

- Every pull request keeps the game playable end to end (menu, driver selection, combat, result). No long-lived branch, no feature flags, no parallel code paths (CLAUDE.md). Each PR replaces one layer wholesale behind an API that the next PR deletes (the renderer facade in phase 1, the bitmap-mask text mode in phase 2, the input singleton in phase 3); nothing runs two paths side by side.
- Every PR cites the specification rules it implements in its description and lands the tests those rules require.
- Lint zero (R13.29) is a merge gate from the moment the lint exists: first on the gallery, then on every screen as each is migrated.
- Screens are kept working, not polished, during the engine phases. Polish is phase 6, on the new engine, with the gallery and lint as the bar.
- Three deliberate re-baselines of the screenshot goldens: when ordering changes (phase 1), when text metrics change (phase 2), when button and input styles start being honoured (phase 4). Each is its own PR with nothing else in it.
- Conventions from CLAUDE.md apply to all new engine code: tabs, named-argument constructors, accessors, delete legacy code rather than keep it.

## 5. Toolchain decisions that the phases depend on

- Fonts: three roles (R11.8). Body is Open Sans (already in the repo under `public/assets/fonts/`, SIL OFL 1.1; move it under `src/assets/fonts/` with its licence file). Display and mono faces are chosen at the start of phase 2 from OFL faces (candidates: a condensed display face; JetBrains Mono or Roboto Mono). Arial cannot be bundled. Atlases are generated by `msdf-atlas-gen` (`-type mtsdf -size 48 -pxrange 8 -yorigin top`, which satisfies R6.4a's range ratio of at least 1/6 so 12 px text on a 100 percent Windows desktop still has a 2-pixel range) through `scripts/build-fonts.(ps1|sh)`, run by hand when a face or the charset changes; the PNG and JSON outputs are committed under `src/assets/fonts/`; the JSON schema is msdf-atlas-gen's (R6.2). The charset file holds the R6.3 ranges. Sizes below 9 logical px at ratio 1 fall back to a platform-rasterised atlas (R6.4a); the token scale defines no text size below 11 px.
- Icons: an icon atlas from an OFL or MIT icon font (Tabler Icons or Lucide), built by the same script, addressed through a generated `icons.ts` (R12.6). The six symbol glyphs the screens use today (⛽ 🛡 🔧 ⚙ ⛡ ←) migrate to it.
- Tokens: `src/renderer/engine/theme/tokens.json` and a committed generated `tokens.ts`, produced by `scripts/generate-tokens.mjs` (plain JavaScript so it runs on the CI Node), with a unit test that regenerates in memory and fails on drift (R11.2).
- Dev-only code: a `DefinePlugin` constant `__DEV_TOOLS__` declared in `types.d.ts` and set in the Jest setup; dev code wrapped in `if (__DEV_TOOLS__)`; the gallery is a fourth webpack entry emitted in development builds only (R13.2, chapter 13 mapping table).
- Tests: Jest stays. Engine modules are importable without a DOM (R14.1); the null and recording backends make the batcher, clip stack, layout, text layout over the committed metrics, tokens, snapshot, and lint unit-testable. Micro-benchmarks run through a `tinybench` script over `*.bench.ts` files outside Jest's match pattern. `collectCoverage` moves to `test:coverage` (DDB-19).
- Visual tests: `@playwright/test` with a `webServer` serving the gallery, projects `chromium` (launch args `--use-gl=angle --use-angle=swiftshader-webgl --enable-unsafe-swiftshader`, R15.33) and `electron`; a `visual.yml` workflow; goldens committed per project and platform and produced only by the CI image (R14.5); the Clock API and the engine's injectable clock for determinism (R15.36).
- Runtime floor: the six-argument DevTools timestamp hook needs Chromium 134 (R15.42); Electron 25 (Chromium 114) uses the `performance.measure` path or feature-detects until the Electron upgrade in the toolchain epic (DDB-22) lands, which should happen before the tooling phase.
- Card art: a runtime-packed texture array with mipmaps and a residency budget, metered uploads, and placeholders while art decodes (R5.30 to R5.35); the art pages join the resident texture set with the three font atlases and the icon atlas so a screen is one GPU draw per flush (R5.20).
- Assets: JSON as bundled modules, atlas images as webpack asset modules (`asset/inline` for the Electron renderer), no `fetch` from the engine (R15.34); this also fixes DDB-52 for the engine's own assets. TypeScript `lib` and `target` move to ES2022 (R15.41).
- Context: WebGL2 with the R15.2 attributes; WebGL1 support ends.

## 6. Phases

Each phase lists its deliverables as the checkboxes that become board tasks. The first three phases correspond to the three pull requests the implementer review worked out file by file ([04-implementer.md](../ui-rendering-spec/review/04-implementer.md), "First three PRs").

### Phase 0: safety net and baseline (chapters 13 and 14, partial)

- [ ] Tree snapshot over the existing `Layer` tree (`window.__ui.tree()`): id, type, bounds, screen bounds, visible, children, viewport (R13.21 to R13.24); `id` added to `LayerOptions` and set on the roughly thirty named game elements.
- [ ] Layout lint as a pure function with the seven required rules (R13.25 to R13.28), unit-tested on hand-built trees, exposed as `window.__ui.lint()`.
- [ ] Gallery routing: the developer screen's sections become scenes in a registry addressable by `?scene=` (R13.30 to R13.33), as a dev-only webpack entry.
- [ ] Playwright, the SwiftShader flags, `visual.yml`, one screenshot spec per screen and per gallery scene, committed goldens (R14.5, R15.33, R15.36).
- [ ] Input injection hook (`window.__dev.input(...)`) feeding the existing input path in logical coordinates (R13.35).
- [ ] Frame timer with disjoint sections and window statistics (R13.7 to R13.11) replacing the frame-interval-only monitor; batcher counters arrive with phase 1.
- [ ] Baseline table recorded and committed under `perf-results/`.
- [ ] Dead engine code removed (DDB-14, DDB-15, with the correction that `RenderContext.ts` is live today and `RendererContext.ts` is the singleton to retire in phase 3); `removeChild` gains an unmount as a one-line stopgap for the registration leak.

### Phase 1: draw core (chapters 2, 3, 4, 5, 7, 15)

- [ ] WebGL2 backend: R15.2 context, context-loss handling, fixed-capacity buffer rings, per-frame uniform block, `texStorage2D` textures, no synchronous GL calls (15.3 to 15.5); null and recording backends (R2.21, R2.22).
- [ ] Uber shader with explicit modes `flat`, `rect`, `shadow`, `circle`, `image`, `text` (plus a temporary `mask` mode for the old bitmap atlas, deleted in phase 2): SDF rounded rect with per-corner radii and inside, center, outside borders with RGBA border colour composited by exact coverage (R5.5 to R5.10), the linear one-pixel ramp and inflated quads (R5.6, R5.7), box shadow and glow with three-sigma padding (R5.11 to R5.13), premultiplied output with `additive` free (R5.22, R5.22a), CPU feather for polygons (R5.17).
- [ ] Draw API: frame lifecycle, transform, clip, opacity, and layer stacks, the draw calls of chapter 2 (`drawText` adapts the old atlas until phase 2), `measureText`, `getStats`.
- [ ] Batcher: one draw group per call, layer ordinal key, per-layer partition with the single-layer fast path, barriers (R3.3 to R3.24); the resident texture set with per-draw slot selection (R5.20); counters with split and flush reasons, `culled`, `occluded` (R13.12 to R13.15).
- [ ] Clip stack with three states, screen-space conversion at push, per-draw clip data tested on an interpolated logical position, CPU cull of draws outside the clip, no scissor state and no `getParameter` (R4.1 to R4.8); content offset before clip (R4.9 to R4.11).
- [ ] Resource layer: texture ownership with reference counts, `texStorage2D` allocation, metered uploads, context-loss recovery; the card-art texture array and residency budget can follow in phase 6 when art lands (R5.30 to R5.35).
- [ ] Coordinates: logical pixels, `dpr` confined, projection per flush, `ResizeObserver` sizing, text-run snapping hook (chapter 7, R15.4).
- [ ] Facade: the existing `Renderer.draw*` methods forward to the draw API and `enableScissor` becomes `pushClip` in logical pixels; `Rectangle` passes radius, border position, gradient, shadow; leaves render through the batcher; `Game.render` calls `beginFrame` and `endFrame`. Deleted in the same PR: `ScissorBatcher`, `Texture`, `Arrow`, `TextRenderer`, `Renderer.drawLine`, the old shaders, the scissor save-and-restore code.
- [ ] Ordering and clipping unit tests on the recording backend (3.12, 4.7); the chapter 5 pixel fixtures in the gallery.
- [ ] The known reorder sites fixed in the same PR with a screenshot pass of all screens (spec 14.6): the card title moves past the driver badge; the deck preview gets a scroll container or hug sizing; the developer screen's panel sits below the title's line box; the card showcase's double render is deleted.

Visible result: text can be covered by later shapes, rounded corners and borders render at about thirty-five sites, shadows exist, hand clipping is correct at every window size, nested clips intersect, one GPU draw per frame per texture, the F5 overlay shows real draw and flush counts.

### Phase 2: text (chapter 6)

- [ ] Font pipeline per section 5: faces, licences, `charset.txt`, `build-fonts` script, committed atlases, loader with R6.2 validation.
- [ ] Metrics service: shared measure and render iteration, kerning, letter spacing, transform, ascent centring, greedy wrap with `Intl.Segmenter`, ellipsis, decoration, measurement cache keyed on role (6.3, 6.4).
- [ ] `text` mode (median of three, derivative range), run-origin snapping, text shadow (6.2, 6.5); the `mask` mode, `FontAtlas` canvas rasterisation, and the old text batching deleted.
- [ ] `Text` component on real metrics: top-left line box, roles, `fontWeight` through the theme table, `fontFamily` alias, `nowrap` plus `ellipsis` truncates (R12.4); the estimate sites (`Text.layout`, wrapping, the synergy panel, driver stats, the input caret) replaced.
- [ ] Icon atlas and the six symbol-glyph sites (R12.6).
- [ ] Electron packaged build smoke-tested for the asset path (R15.34).

Visible result: crisp text from 8 to 64 px in the new faces, centred titles centred (DDB-30), bold titles bold, symbols rendered; every measured layout shifts once and the goldens are re-baselined deliberately.

### Phase 3: object model, input, focus (chapters 8 and 9)

- [ ] Component base: the R8.2 properties including `pointerEvents`, `transform`, per-side margin, and the base callbacks; effective values; parent back-reference; `render()` emits own draws only; no implicit children; `moveChild` and `reconcileChildren`; `removeChild` unmounts; mount context replacing the input and renderer singletons; idempotent unmount and mount-on-add; upward invalidation to relayout boundaries; `screenBounds` and the conversions; frame order with the event queue drained at frame start (R8.1 to R8.29).
- [ ] Clock and animator with tweens, retargeting, and reduced motion (R8.28); no platform timers in UI code (the hand layer's `setTimeout` goes).
- [ ] Dispatcher: hit-test pre-pass over layers and reverse submission order, clip-, offset-, transform-, and `pointerEvents`-aware; public `hitTest`; bubble; framework-derived enter, leave, and `hovered` on ancestors; click on the nearest common ancestor with the drag threshold; pointer capture per pointer with `lostpointercapture` and cancellation; Pointer Events adapter with `touch-action: none`; normalised wheel with latching (chapter 9). `InputSystem` is deleted; its registration methods survive only as the root hotkey table.
- [ ] Focus manager: tree-derived tab order, scopes as subtree roots, focus fixup, focus groups, focus-visible, directional focus, `activate` and `cancel`, scoped hotkeys with text fields owning printable keys (9.6, 9.7).
- [ ] Drag service with `dragenter`, `dragover`, `dragleave`, `drop`, `dragend`, and `accept()` (R9.12).
- [ ] Popup, tooltip, placement, overlay, clipboard, and asset-cache services in the mount context (12.8).
- [ ] Game code moved onto the tree: `Card` and `Vehicle` extend the base and use `handleEvent` (no constructor registration, no render bypass, no child rebuild on resize); the ten `children[n]` sites become named fields; the three screens with window-size reads use the root; driver selection stops rebuilding on resize; the combat screen gets its one layout (phase 4 makes it a stack); the splash fades through root opacity (DDB-41).
- [ ] Snapshot and lint move onto the new tree with the full R13.22 schema.

Visible result: overlapping vehicles receive one click; scrolled-out or hidden components stop receiving clicks; a button is hovered over its label; drags survive leaving the widget; Tab moves focus; Escape reaches the combat screen; the splash fades.

### Phase 4: layout and theme (chapters 10 and 11)

- [ ] Stack container: fixed, hug, fill with weights, six distributions, four cross alignments and `alignSelf`, per-pass resolved sizes, the three passes with shrink-to-fit and safe alignment, `minSize`, `maxSize`, `aspectRatio`, negative gap, absolute children with anchor and pivot, roots sized from the viewport (chapter 10); worldsim's layout suite ported as the conformance suite plus the added cases (10.9).
- [ ] Combat screen as the first stack consumer: bands 25/40/20/5 with the turn counter and log as anchored absolute children (the chapter 10 worked example); the second layout deleted.
- [ ] Token file, generator, committed `tokens.ts`, drift test (R11.1 to R11.4); the two-accent, five-surface, radius, spacing, type-role, and `control` tokens as the starting theme (11.2).
- [ ] Framework-maintained state flags, layered state resolution, closed style property set rejected rather than ignored, override semantics, token-driven transitions (11.3, 11.4). `Button` and `Input` stop ignoring their style objects; the START RUN and END TURN colour hacks become variants.

Visible result: every button changes appearance once (they ignore their styles today), so this phase is the third deliberate re-baseline; resizing the combat screen re-runs one layout.

### Phase 5: component catalog (chapter 12)

Waves, each landing with its gallery scene, behaviour tests, and lint zero:

- [ ] Wave A: Rectangle, Circle, Line, Text, Image, Icon, Button, ListRow, Checkbox, Toggle, RadioGroup, FocusGroup, Container, Stack, Panel, ScrollContainer with the standalone Scrollbar (real scrolling, `scrollIntoView`, wheel latching, `tabIndex: -1`; closes DDB-32).
- [ ] Wave B: TextInput, NumberInput, Menu, Select, DropdownButton, ContextMenu, Slider, TabBar, SegmentedControl.
- [ ] Wave C: Dialog (overlay service, dismissal defaults, focus trapping), Popover, Tooltip with component content, Toast and ToastStack, ScreenTransition, ProgressBar, Counter, Badge, TreeView, Avatar, Stat, KeyCap, Divider.

### Phase 6: screen migration and polish

- [ ] Combat: the hand as a stack with negative gap, cards with `transform` for the fan, `zIndex` and `raised` for hover lift through the animator, drag targeting through the drag service with `dragenter` highlights and a preview line in `overlay`, card previews through the tooltip factory, the turn banner in `overlay`, enemy intent and status icons through Icon, floating damage numbers spawned at `screenBounds`. Closes DDB-28, DDB-29, DDB-30; sets up DDB-33, DDB-34, DDB-37, DDB-47.
- [ ] Driver selection: stacks for the panels and the synergy panel, a scroll container for the deck preview (DDB-31), a Select for driver choice, no rebuild on resize.
- [ ] Main menu, splash, battle result: root stacks, centred titles, transitions through ScreenTransition.
- [ ] Settings and credits screens (DDB-38) as the first screens authored entirely on the new catalog (dialog, checkbox, slider, select).
- [ ] Every screen at lint zero with a golden; the developer screen's sections are gallery scenes on the new components; the accessor rename landed as its own mechanical PR.

### Phase 7: observability completion and conformance

- [ ] GPU timer with one query per pass and disjoint handling (R13.16 to R13.20), the perf capture script (required, R13.38) and comparison table (13.8), the perf overlay drawn through the renderer, DevTools tracks (R15.29) with feature detection (R15.42).
- [ ] Conformance re-score of chapter 14's table for this engine; remaining gaps become follow-up tasks.
- [ ] Deferred and optional: off-screen group opacity composite, stencil clips, the gamepad adapter (DDB-51), the UI scale setting (R7.5), instruction-list reuse (R8.19), cross-fade transitions.

## 7. Board structure (to create when implementation starts; nothing has been created)

One epic, "UI rendering engine (layered UI rendering spec)", with this document linked as its spec and the decision record noted. Children are the checkbox groups above, one task per coherent pull request (about thirty tasks), with blockers set explicitly: phase 0 tasks have no blockers and can start at once; phase 1 blocks phases 2 and 3; phase 3 blocks phase 5; phase 4 blocks phases 5 and 6; phase 5 waves block the screen tasks of phase 6; phase 7 follows phase 6.

Existing items this epic subsumes or unblocks, to be linked rather than duplicated: DDB-28, DDB-29, DDB-30, DDB-31 (blocked by phases 1 and 2, closed by phase 6), DDB-32 (closed by Wave A), DDB-41 (closed by phase 3), DDB-14 and DDB-15 (folded into phase 0 with the `RenderContext` correction), DDB-38 (phase 6), DDB-37 and DDB-47 (built on phase 6's hand and drag service), DDB-50 and DDB-51 (phase 7 deferred items), DDB-52 (the engine's own assets follow R15.34; game data still needs its own fix). Toolchain items DDB-16 to DDB-22 are independent, but DDB-18 (tsconfig), DDB-19 (Jest), and DDB-22 (Electron upgrade) are worth landing before phases 1 and 0's tooling respectively.

The board holds no copy of this document; tasks carry a one-line description and a pointer to the phase and the spec rules. Item status is kept current per the Specboard workflow, and discovered work is filed with `discovered_from`.

## 8. Success criteria

- Every required item in spec chapter 14's table scores yes for this engine for chapters 1 to 13 and 15.
- Lint zero on every screen and gallery scene; a screenshot golden per screen and scene in CI.
- The rendering bugs DDB-28, 29, 30, 31 and the blocked features DDB-32 and 41 closed by the phases that own them.
- Combat screen at 1440x882: under 40 GPU draw calls per frame (today roughly one per shape), frame p99 under the display's refresh interval, no per-frame allocations in the batcher.
- `npm test` and `npm run lint` green on every PR; the 126 mechanics and AI tests untouched throughout.

## 9. Risks

- Text-above-shapes reliance in every screen: phase 1 lands with a visual pass of all screens and the four known layout fixes (spec 14.6).
- `children[n]` indexing, render bypasses, constructor-time registration, rebuild-without-unmount: phase 3 replaces them; phase 0's stopgap unmount limits the leak until then.
- Style application suddenly working changes the look of about thirty-five rounded rects, twenty-three buttons, and five inputs at once: phase 4 is the deliberate re-baseline.
- Font and icon pipelines need a native tool and licence decisions: settled at the start of phase 2, not later.
- Old Electron for the DevTools hooks: feature detection until DDB-22 lands.
- All five reviews are resolved into draft 4 and chapter 17 of the specification records every finding with its outcome; the rules the phases cite are stable unless a later revision withdraws one, in which case the withdrawn number stays in the text.
