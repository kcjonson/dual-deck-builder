# 12. Component catalog

Status: draft 4 (2026-09-07; revised after all five reviews, see chapter 17)

The components a conforming implementation provides, with the behaviour each must have. Visual details are given at the token level (chapter 11) so a theme can restyle without changing behaviour. Where worldsim has a test file for the component, that file is the behavioural contract and should be ported as the conformance test; those are marked "tests: port". Everything here is a real component in the tree (chapter 8, R8.1); the worldsim split between tree widgets and draw-only primitives is not carried over. The review added the components a card game needs that worldsim never had (popover, focus groups, screen transition, counters) and tightened the contracts that were too thin to test.

Rules are numbered R12.n. Every component also obeys the shared rules: named-argument constructor, accessors, the closed style set, `id`, `visible`, `enabled`, `opacity`, `layer`, `zIndex`, `margin`, sizing modes, `transform`, `pointerEvents`, `cursor`, `tooltip`, the base callbacks, and controlled-value semantics where it has a value (a value set programmatically never fires `onChange`; a user change fires it once, with the new value already applied).

## 12.1 Leaves

- R12.1 Rectangle: `size`, `fill`, `border` (`color`, `width`, `position`, `radius` or per-corner radii), `gradient` (per-corner colours), `shadow` (`color`, `blur`, `spread`, `offset`). One draw group (two with a shadow). Resizable by layout.
- R12.2 Circle: `radius`, `fill`, `border`. SDF disc (chapter 5, R5.15). Not resizable by layout unless the implementation chooses to scale the radius.
- R12.3 Line: `start`, `end`, `color`, `width`, optional round caps. Position moves both endpoints. A polyline (a curved path on a map, flattened game-side) is a sequence of capsule lines; `drawPolyline` in the draw API is optional.
- R12.4 Text: `text`, `font` (role: `display`, `body`, `mono`), `fontSize`, `fontWeight`, `color`, `align` (left, center, right), `verticalAlign` (top, middle, bottom), `wrap` (none, word), `overflow` (visible, clip, ellipsis), `letterSpacing`, `transform` (none, uppercase), `decoration` (none, underline, strike; a 1 px rect per line after the glyph run in the text colour), `shadow`. `position` is the top-left of its line box, which is its bounds; the baseline anchor of the draw API is hidden by the component. Hug by default; an assigned or constrained width sets the alignment box and wrap width (chapter 10, R10.13); its default main-axis minimum is its longest unbreakable word (R10.4). Vertical centring is on the font ascent (chapter 6).
- R12.5 Image: `texture`, `sourceRect` (UV or pixel rect; sprite frames are `sourceRect` changes), `tint`, `fit` (`fill`, `contain`, `cover`, `none`), `placeholder` (a fill colour or nothing), optional nine-slice insets. Layout size is `size` or `aspectRatio`, never the texture's; a texture that is not yet resident draws the placeholder and the component requests a re-render when it becomes resident. Textures are owned by the asset cache in the mount context; components hold handles. Required for a card game whose art is bitmaps; worldsim has no image primitive because its art is vector.
- R12.6 Icon: `glyph` (a name from the generated icon set), `size`, `tint`, or `svg` (a path) where the implementation supports vector icons. The baseline icon is a distance-field glyph from an icon atlas built by the same pipeline as the text atlases (chapter 6) from an icon font (Tabler Icons and Lucide both ship static fonts under permissive licences), addressed by name through a generated `name -> code point` module and drawn in `text` mode with `size` and `tint`; polyline and tessellated icons MAY be supported in addition. Arrows, chevrons, geometric marks, and pictograms come from the icon atlas, never from the text faces; the sibling engine's six symbol glyphs rendered as nothing for that reason.

## 12.2 Buttons and rows

- R12.7 Button: `label`, `icon`, `iconPosition` (`left`, `right`, `only`), `variant` (`primary`, `secondary`, `ghost`, `danger`, `data`), `size` (`sm`, `md`, `lg`), `block` (fill width), `disabled`, `onClick`, `focusable` (true), `tabIndex`; `pointerEvents` defaults to `unit`, `cursor` to `pointer`. State machine: `pointerdown` inside sets pressed and captures; `pointerup` inside fires `onClick` (through the synthesised `click`) and returns to hover; up outside returns to normal without firing; `activate` fires `onClick` when focused; repeats ignored. Visual state from chapter 11, R11.12, including the 1 px pressed nudge and the focus-visible ring. The label is measured with the same transform and tracking it renders with. Tests: port (button state machine), plus hover through the label, focus ring visibility, keyboard activation, no click after a drag-threshold move.
- R12.8 ListRow: `label`, `trailing` (right-aligned mono text), `selected`, `dim`, `indent`, `onClick`. Same press machine as Button, left-aligned, never uppercase; hover wash, selected wash with a 2 px accent bar on the left, bottom hairline. Selection is owned by the parent list (a focus group, R12.34); the row only reports clicks. Worldsim added this because a button cannot be a row; do not make lists out of buttons.
- R12.9 Checkbox and Toggle (switch): `checked`, `label`, `disabled`, `onChange(checked, event)`, `indeterminate` (checkbox only). The whole row including the label is the hit area and a focus target; `click` and `activate` from Space toggle (Enter does not); an indeterminate checkbox becomes checked on toggle; Toggle is a Checkbox with a different look and no indeterminate state. Worldsim has neither; a settings screen needs both.

## 12.3 Text entry

- R12.10 TextInput: `value`, `placeholder`, `maxLength`, `password` (masked), `disabled`, `onChange`, `onSubmit`, `validator` (a synchronous predicate that rejects a character or a resulting value before the change is applied), `selectAllOnFocus`. Behaviour: pointer down focuses and places the caret at the nearest glyph boundary; drag (with capture) selects; Shift with arrows extends; Home and End; Delete and Backspace (selection first); clipboard cut, copy, paste, select-all via the context clipboard; paste strips control characters; Enter fires `onSubmit`; Escape is left unconsumed so an enclosing dialog receives it; the caret blinks at 0.5 s from the context clock with the timer reset on any edit or focus gain; horizontal scroll keeps the caret visible and snaps to zero when the text fits; text is clipped to the padded content box (chapter 4, R4.5); the field consumes every other key it receives while focused (chapter 9, R9.15). Out of scope for the baseline: multi-line, undo, IME composition beyond what the platform delivers as `char`. Tests: caret placement, selection with drag and keys, clipboard, maxLength, validator, clipping, Escape passes through.
- R12.36 NumberInput (stepper): `value`, `min`, `max`, `step`, `precision`, `onChange`, with increment and decrement buttons, Up and Down arrows, and wheel when focused; typed text is committed on blur or Enter and clamped. Recommended.

## 12.4 Selection controls

- R12.11 Menu (building block): `items` (`label`, `onSelect`, `enabled`, `separator`, `shortcut`), `width`, `hoveredIndex`, `maxHeight`. Item height from tokens; hover on move (not consumed); pointer down inside consumed; pointer up on an enabled item selects. A menu taller than the rect the placement service returns scrolls internally. No positioning logic of its own; lives in the `popup` layer when shown. Tests: port (26 tests); `separator`, `shortcut`, `maxHeight`, and internal scrolling are additions to the ported suite.
- R12.12 Select: `options` (`label`, `value`), `value`, `placeholder`, `disabled`, `onChange`; `popupTrigger` true. Opening highlights the current value; `activate` toggles or picks; Up and Down move (Down opens); Escape closes; focus loss closes (focus moving into the menu keeps the select focused, chapter 9, R9.23). The caret is an Icon. Tests: port.
- R12.13 DropdownButton (menu button): `label`, `items`, `openUpward`, `onSelect`; `popupTrigger` true. Toggles on release; opens on Down; closes on outside press (consumed, except on another trigger), focus loss, Escape, or after selection. Tests: port.
- R12.14 ContextMenu: `items`, `onClose`; `openAt(screenPoint)` places the menu at the pointer through the placement service (flip or clamp inside the viewport); the press that opened it is captured so its release cannot select an item; Up and Down wrap and skip disabled; `activate` selects; Escape closes; a primary press outside closes and is consumed; a secondary press outside closes without consuming so the scene can open a new menu at the new point. Tests: port.
- R12.15 Slider: `min`, `max`, `step` (0 for continuous), `value`, `logScale`, `label`, `valueFormatter`, `detent` (normalised position of a snap tick), `disabled`, `onChange`. Math (normative, from worldsim): position to value is `min * (max / min) ^ t` when logarithmic with positive bounds, linear otherwise; invalid logarithmic bounds fall back to linear and never produce NaN; `value` set programmatically clamps then snaps to step silently; a user change fires `onChange` once; a `value` set from inside `onChange` commits without re-firing (chapter 8, R8.25). Interaction: press within the thumb's hit radius drags with pointer capture; press elsewhere jumps then drags; arrows step by `step` or 1% of the range; Home and End. Visual: pill track, filled portion, detent tick, thumb with glow, disabled greys. Tests: port.
- R12.16 TabBar: `tabs` (`id`, `label`, `disabled`), `selectedId`, `onSelect`. Controlled when `selectedId` is supplied: an unknown or disabled id renders no selection and the parent is expected to supply a valid one; uncontrolled when it is omitted: the bar manages its own selection, starting at the first enabled tab and firing `onSelect` on user changes only. Selection on release over the pressed tab; a focus group (R12.34) with Left and Right moving to the next enabled tab; `onSelect` never fires for the already selected tab. Visual: labels measured uppercase with tracking, 2 px accent underline on the bar's hairline, hover treatment.
- R12.17 SegmentedControl: `options`, `selected`, `size`, `tone`, `onChange`. An inset well with a glowing filled chip on the selected segment; equal segment widths from the widest label unless a `segmentWidth` is given; a focus group. Interactive (worldsim's was draw-only).
- R12.35 RadioGroup: a focus group of radio items with one `value`, `onChange`, arrows moving selection, Space selecting. Required.

## 12.5 Containers

- R12.18 Container (children, clip, content offset, no visuals; `pointerEvents` default `passthrough`) and Stack (chapter 10). Library containers MUST NOT insert implicit children: `children` contains exactly what the caller added, in insertion order, and `getChildren()` never returns the render-order view. The sibling engine's panel inserted a background and a content layer and redirected child access to the content layer, and ten call sites indexed `children[n]` around it.
- R12.19 Panel: `title`, `kicker`, `variant` (`panel`, `raised`, `inset`), `accent` (`accent`, `data`, `none`), `corners` (bracket ticks), `compact`, `flush`, `glow`, `actions` (a slot laid out in the header's right end), and a content slot that is a stack container by default; `pointerEvents` default `auto` so a panel occludes what is beneath it. Header band only when a title or kicker exists; hairline under it; drop shadow for `raised`, none otherwise; the bracket ticks are four L shapes straddling the border in the accent colour. Content is inset by the background's corner radius unless the implementation clips with the rounded-rect clip (chapter 4, R4.14), and always when a second rounded clip would nest inside it (R4.14's nesting rule keeps only the innermost rounded clip).
- R12.20 ScrollContainer: vertical scrolling of one content child (usually a stack), `scrollTo`, `scrollBy`, `scrollToTop`, `scrollToBottom`, `scrollIntoView(child, { block: nearest | center })`, `contentHeight` (auto from the child, override allowed); `focusable` with `tabIndex: -1` (focusable by press and programmatically, not in Tab order); a press on the track or thumb sets `preventFocus` so it does not steal focus from a field inside. Track and thumb (the standalone Scrollbar, R12.37) drawn only when content overflows; thumb size proportional with a minimum; thumb drag with capture maps pointer delta to scroll; track click jumps; wheel per chapter 9, R9.32 (normalised pixels, latching); Page Up, Page Down, Home, End when focused. The clip is inset by the largest `inkExtent` of a direct child when padding allows (chapter 8, R8.8) and by the background radius unless the rounded clip is implemented. Horizontal scrolling and smooth scrolling are optional. Tests: port (max scroll, clamping, viewport resize re-clamps), plus wheel latching and clip-aware hit testing.
- R12.21 Dialog: `title`, `kicker`, `size`, `modal` (true), `footer` (slot for right-aligned actions), `dismissOnOutsidePress` (false), `closeOnEscape` (true), `onClose`. Opened and closed through the overlay service (chapter 8, R8.21), which owns it as a root for the whole animation. State machine `closed`, `opening`, `open`, `closing` with token-timed fades (`dur` in, `dur_fast` out) and the emphasised entrance (scale 0.96, translate 8 px) through the animator; `open()` is ignored unless closed, `close()` unless open or opening; Escape closes only when fully open and `closeOnEscape`; the X button always closes; an outside press closes only when `dismissOnOutsidePress`, and modal dialogs consume the press either way while non-modal dialogs never consume it (a stray click must not dismiss "Abandon run?"). Modal dialogs draw a full-viewport scrim in the `modal` layer with `pointerEvents: auto` that consumes pointer events from its first frame (chapter 3, R3.29) and push a focus scope on their subtree (chapter 9, R9.20). Content is authored in content-local coordinates and clipped to the content rect. Centred in the viewport by anchor. Tests: port (18 cases), plus focus trapping, dismissal defaults, and first-frame blocking.
- R12.33 Popover: an anchored, interactive, non-modal floating surface (a card inspector, a stat breakdown): `anchor` (a component or a screen point), `preferredSide`, `layer` (`overlay` default, `popup` when it must beat menus), `dismissOnOutsidePress` (true, never consuming), `closeOnEscape` (true); placed by the placement service; never takes focus unless it contains focusables, in which case it pushes no scope. Tooltip is the non-interactive special case. Required.
- R12.34 FocusGroup (List): a container with `focusGroup: true` (chapter 9, R9.29): `orientation`, `wrap`, `activeChild`, `selected` (single or multiple), `onSelect`, `onActivate`, optional type-ahead. A list of ListRows is a FocusGroup; so are menus, tab bars, segmented controls, radio groups, and toolbars. Required.

## 12.6 Transient surfaces

- R12.22 Tooltip: `content` (`title`, `description`, `hotkey`) or a factory `() => Component` whose tree the service mounts under the tooltip root in the `tooltip` layer (a full-size card preview) and unmounts on hide; `maxWidth`. Declared on any component through the `tooltip` property; the tooltip service drives it from the dispatcher's enter and leave events and from keyboard focus (a tooltip must be reachable without a pointer): `idle`, `waiting` (`tooltip_delay`), `showing` (`dur_fast` fade), `visible`, `hiding` (80 ms fade), `idle`; moving between two tooltip owners while visible swaps content without the delay; pointer movement under `hover_move_tolerance` is ignored; placement by the placement service, default below-right of the pointer with flip and clamp; hidden on any `pointerdown` on its owner, while a pointer is captured, and while a drag is active; MAY show on `contextmenu` for touch. Size comes from measured text or the mounted tree, not from a per-character estimate. Never consumes input. Tests: port (state timing, flips, never consumes), plus keyboard trigger and drag suppression.
- R12.23 Toast and ToastStack: `title`, `message`, `severity` (`info`, `warning`, `critical`), `autoDismiss` (seconds, 0 for persistent; paused while the toast is hovered), `onDismiss`, `onClick`; lifecycle `appearing` (`dur`), `visible`, `dismissing` (`dur_slow`), `finished` through the animator; the X dismisses, a click elsewhere fires `onClick` then dismisses. The stack is an overlay root anchored to a corner, stacks away from it, caps live toasts (oldest dismissed first at capacity), repositions on add, removal, and anchor move, reports the envelope of live toasts as its bounds, is invisible while empty, and exposes counts by severity. Newest first for input, oldest first for paint; `toast` layer. Tests: port, plus hover pause.
- R12.38 ScreenTransition: an overlay root in the `transition` layer: a full-viewport quad whose opacity is tweened; the scene manager runs fade out, unmount outgoing roots, mount incoming, one layout, fade in, and blocks input while active (chapter 8, R8.22). A cross-fade showing both scenes MAY be implemented by rendering the outgoing scene once into an off-screen target and compositing it as an Image beneath the fade. Required (the fade); the cross-fade is optional.

## 12.7 Data display

- R12.24 ProgressBar (meter): `value` (0 to 1), `tone` (`auto` bands by value), `label`, `valueText`, `size`, `segmented`, `inline` (label and value drawn inside the track with a dark text shadow). Fill animates over `dur_slow` through the animator.
- R12.39 Counter: a Text whose displayed number tweens toward `value` over `dur_slow` with a formatter; health and resource readouts. Recommended.
- R12.25 TreeView: `nodes` (`label`, `count`, `children`, `expanded`), `rowHeight`, `indent`, `onExpand`, `onCollapse`, `expandAll`, `collapseAll`; a flattened row list rebuilt lazily; the chevron column toggles; optional selection with `onSelect` (worldsim's was view-only); a focus group with Up, Down, Left (collapse), Right (expand); rows outside a fixed height are culled and clipped. Tests: port.
- R12.26 Badge: `label`, `tone`, `dot`, `outline`. A pill sized from the measured label; `measureWidth` is public for hand layout.
- R12.27 Avatar: `seed`, `size`, `mood` (0 to 1), `selected`. Deterministic hue from a 32-bit FNV-1a hash of the seed, initials from the first two words, mood ring colour banded at 0.30 and 0.55.
- R12.28 Stat: `label`, `value`, `unit`, `tone`, `size`, `align`. Label above value, unit trailing at 0.62 of the value size, baseline aligned.
- R12.29 KeyCap and Divider: a key label in a small extruded cap; a hairline with an optional centred caption.
- R12.37 Scrollbar: a standalone track and thumb bound to any `{ offset, extent, viewport }` pair, so horizontal scrolling and custom scroll views (a wide hand, a map) reuse one implementation; ScrollContainer composes it. Recommended.

## 12.8 Services (in the mount context)

- R12.30 Placement: `place(anchorRect, size, preferredSide, viewport, gap)` returns a screen rect for popups, popovers, tooltips, and menus: try the preferred side, flip to the opposite side on overflow, then clamp inside the viewport with `gap` from the edges. One implementation for every popup; worldsim had two placement routines (one flips, one clamps) and one manual open-upward flag. Callers convert the result to local coordinates with `screenToLocal` (chapter 8, R8.13).
- R12.31 Popup: tracks the open exclusive popup (menu, select, context menu) and closes it when another opens, on outside press (chapter 9, R9.13), on Escape, and on focus loss.
- R12.32 Overlay (chapter 8, R8.21), tooltip, drag (chapter 9, R9.12), clipboard, and asset cache services as described; font metrics (chapter 6); focus manager (chapter 9); animator and clock (chapter 8, R8.28).

## 12.9 Game-specific composites and scope

Cards, vehicles, hand fans, and the like are built from the catalog and the draw API by the game, not by the library. The library owes them: image and text leaves, `transform` for fanning and scaling, sibling `zIndex` for overlap with a negative stack gap, the `raised` and `drag` layers, the drag service with `dragenter` and `drop`, `screenBounds` for spawning damage numbers and preview lines, the animator for lifts and flights, `reconcileChildren` for a hand that changes every turn, and the `tooltip` factory for card previews. Sprite animation is `Image.sourceRect` changes in `update(dt)`; particles are game-side, drawn with `drawImage` or `drawPolygon` in `overlay` or as a foreign GPU pass behind barriers (chapter 2, R2.15); curved paths are polylines of capsule lines tessellated game-side; pinch gestures and vector art beyond icons are out of scope (chapter 1, R1.6); a gamepad is a platform adapter (chapter 15) that drives directional focus and a virtual pointer, so components need no gamepad code.

## 12.10 Conformance checklist

| Component | Level |
|---|---|
| Rectangle, Circle, Line, Text, Image, Icon (atlas glyphs) | required |
| Button, ListRow, Checkbox, Toggle, RadioGroup, FocusGroup | required |
| TextInput | required |
| Menu, Select, DropdownButton, ContextMenu, Slider, TabBar, SegmentedControl | required |
| Container, Stack, Panel, ScrollContainer, Dialog, Popover | required |
| Tooltip (text and component content), Toast, ToastStack, ScreenTransition (fade) | required |
| ProgressBar, Badge, TreeView | required |
| Placement, popup, overlay, tooltip, drag, clipboard, asset services | required |
| NumberInput, Scrollbar, Counter, Avatar, Stat, KeyCap, Divider | recommended |
| Horizontal and smooth scrolling, multi-line text input, cross-fade transition, vector icons | optional |
