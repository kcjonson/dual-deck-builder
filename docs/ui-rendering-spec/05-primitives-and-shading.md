# 5. Primitives, shading, and resources

Status: draft 4 (2026-09-07; revised after all five reviews, see chapter 17)

Every visible thing in the UI is one of a small number of primitives, all drawn by one shader program whose behaviour is selected per draw by data, never by binding a different program. That single decision is what keeps a whole screen at one GPU draw call per flush, and what lets chapter 3 order draw groups freely: there is no shader state to preserve between them. The graphics review replaced the first draft's border blend with exact area coverage (the first draft's formula lightened every bordered edge by the fill colour and let the backdrop through translucent borders), pinned the anti-aliasing ramp and quad inflation, sized the buffer rings, made the resident-texture set explicit, and added the resource rules a bitmap-heavy card game needs.

Rules are numbered R5.n.

## 5.1 One shader, data-selected modes

- R5.1 A single program ("uber shader") MUST render all UI primitives. The primitive kind and its parameters travel with the geometry (per vertex, or per instance when the implementation uses instanced quads). Switching primitive kind, colour, border, corner radius, clip, blend mode `over` or `additive`, or opacity MUST NOT change GPU state.
- R5.2 The mode MUST be an explicit enumerated value carried with the geometry. Minimum set: `flat` (vertex colour only, no SDF), `rect` (SDF rounded rectangle with border), `shadow` (blurred SDF rectangle), `circle` (SDF disc with border), `image` (textured quad with tint), `text` (distance-field glyph). Worldsim's tessellated triangles, and with them every line, circle fan, polygon, and icon stroke, reused the `rect` path with zero-size parameters and hit `smoothstep(0, 0, x)`, which GLSL ES 3.00 says has undefined results when `edge0 >= edge1`; it rendered correctly on desktop drivers by luck. An explicit `flat` mode removes the gamble, and ANGLE (the WebGL implementation on Windows) is exactly where luck runs out.
- R5.3 Per-draw data that every mode carries: position (screen space, logical pixels, transform already applied), fill colour (RGBA), clip rect (chapter 4), opacity multiplier (chapter 3, R3.25), blend mode (R5.22a), and the mode. Mode-specific data: rect-local position, half size, corner radii, border colour (RGBA, not RGB), border width, border position, blur, texture coordinates and texture slot, atlas pixel range, rounded-clip parameters (chapter 4, R4.14).
- R5.4 The shape of the per-draw data is normative; its size is not. Data SHOULD be packed with normalised 8-bit colours, 16-bit normalised texture coordinates, and half-float radii and widths (all core WebGL2 attribute types), and values shared by many draws in a flush (clip rects and rounded-clip parameters, gradient corner colours) SHOULD be stored once per flush in a uniform block or data texture and referenced by a 16-bit index per instance, fetched in the vertex stage and passed as flat varyings. A worked 64-byte instance layout: rect `f32x4` (16), texture coordinates `unorm16x4` (8), radii `f16x4` (8), fill `rgba8` (4), border `rgba8` (4), border width `f16` and blur `f16` (4), mode `u8`, border position `u8`, texture slot `u8`, flags `u8` (4), `clipIndex u16` and `gradientIndex u16` (4), 12 bytes spare; it uses about nine vertex attributes of the sixteen WebGL2 guarantees. Inline clips and gradients cost about 96 to 112 bytes per instance and are also acceptable. Four vertices per quad with per-vertex data is acceptable too; it doubles upload bandwidth. Indices on the indexed-quad path MUST be 32-bit (WebGL2 core) so a single flush is not capped at 65k vertices; the instanced path has a six-index unit quad or none.

## 5.2 Rounded rectangles and borders

- R5.5 The rectangle is a single quad. The fragment stage evaluates a rounded-box signed distance (Inigo Quilez's `sdRoundedBox`) from rect-local coordinates, with each corner radius clamped to the smaller half extent so a radius larger than the shape degrades to a capsule rather than an invalid shape.
- R5.6 Coverage of an edge is the linear one-pixel ramp `clamp(0.5 - d / w, 0, 1)`, with `d` the signed distance in the field's units and `w` the device-pixel footprint of one unit (`length(vec2(dFdx(d), dFdy(d)))`, or a per-draw constant when the transform is translate-only); this is the exact box-filter coverage of a straight edge. `smoothstep` and ramps wider than one device pixel MUST NOT be used for shape or glyph edges: worldsim's two-pixel `smoothstep(-px, px, d)` softens every hairline and makes borders look out of focus next to glyph edges. Edges therefore stay one device pixel wide under any transform and any ratio without multisampling; the context is created without MSAA (R5.29).
- R5.7 The quad MUST extend at least one device pixel beyond the outermost SDF edge on every side (the shape edge, or the border's outward extent for `center` and `outside`) while the SDF parameters keep the shape's own size; the extra pixel is where the outer half of the coverage ramp lives. A quad that is exactly the rect never rasterises the pixels whose centres lie up to half a pixel outside the edge, so every fractional-positioned fill and every `inside` border is anti-aliased on the inner side only and animated shapes crawl (Skia inflates rounded-rect bounds by a pixel for this reason). Borders have a width, a colour with alpha, and a position: `inside` (border occupies the shape's interior, the CSS box model and this spec's default), `center` (straddles the edge, the SVG stroke convention), `outside` (grows the visual footprint; used for focus rings). Worldsim's API defaults to `center` while nearly every one of its components overrides to `inside`; the default here follows the components.
- R5.7a Per-corner radii (four values, selected by quadrant in the SDF as in Inigo Quilez's `sdRoundedBox` with a `vec4` radius) SHOULD be supported; joined controls (tab strips, segmented controls, button groups) need them. Per-side border widths MAY be supported (Zed's GPUI evaluates a second inset SDF with quarter-ellipse corners when widths differ).
- R5.8 Border and fill are composited by exact area coverage in premultiplied form. Let `dOuter` and `dInner` be the signed distances to the outer and inner border edges (for `inside`: outer is the shape edge and inner is the shape edge inset by the border width; `center`: outset and inset by half the width; `outside`: outset by the width and the shape edge; the inner rounded box uses radius `max(0, r - inset)`), `co = clamp(0.5 - dOuter / w, 0, 1)` the fraction of the pixel inside the outer edge, and `ci = clamp(0.5 - dInner / w, 0, 1)` the fraction inside the inner edge, with `ci <= co` always. With premultiplied `fillP` and `borderP`, and `borderRegionP = borderP + fillP * (1 - borderP.a)` (the border composited over the fill, CSS `background-clip: border-box`), the fragment output is `(ci * fillP + (co - ci) * borderRegionP) * opacity`. A zero-width border gives `ci == co` and reduces to `co * fillP`; a fully transparent fill with a visible border is legal and gives `(co - ci) * borderP`; a translucent border shows the fill through it and the result is opaque. Fragments with `co < 1/1024` are discarded. The first draft's `mix(fill, border, innerRamp * outerRamp)` double-applied the outer ramp (a one-pixel halo of fill colour around every bordered control) and mixed alpha (the backdrop showed through a half-transparent border); worldsim stores the border as RGB plus width and forces it opaque, so its fades leave borders solid and, worse, its hairline, edge, and strong line tokens (alphas 0.10, 0.20, 0.36; chapter 11, R11.5) render at full alpha on every bordered control today.
- R5.9 Fill SHOULD support a per-corner colour (four colours, interpolated by the rasteriser) to give linear gradients at no extra cost; the design language's buttons and meters use vertical gradients. A gradient MUST NOT break the batch. Per-corner colours are premultiplied before interpolation (on the CPU when packing, or per vertex in the vertex stage), never after, so a gradient to transparent does not darken at its midpoint (CSS gradient semantics).
- R5.10 A rectangle with `cornerRadius` 0, no border, and opaque fill is still drawn through the SDF path so its edges anti-alias identically to its rounded neighbours; the implementation MAY special-case it to `flat` only if it can prove identical coverage at pixel-aligned edges. Abutting SDF edges conflate: two 50 percent coverages compose to 75 percent, a light seam. Components that tile rects edge to edge (tables, segmented controls, split bars, tab strips, meters drawn as two rects) MUST snap the shared edges to the device grid under translate-only transforms (chapter 7, R7.8a) or draw one rect with per-corner colours instead of two.

## 5.3 Box shadows and glows

- R5.11 A shadow is a separate quad emitted immediately before its owner (chapter 3, R3.16). Its geometry is the owner's rect offset by `offset` and grown by `spread`, whose corner radii are the owner's radii plus `spread` (CSS Backgrounds 3, section 6.1.1; for a radius smaller than the spread use `r + spread * (1 + (r / spread - 1)^3)`; negative spread shrinks the radii the same way, clamped at zero), padded on every side by `3 * sigma` (1.5 times `blur`) when the erf form is used and by `blur` when the smoothstep approximation is used, so the falloff has room; a two-sigma cutoff leaves a visible line around large soft shadows.
- R5.12 The shadow alpha follows a Gaussian falloff centred on the spread shape's edge with standard deviation `sigma = blur / 2`, the mapping CSS Backgrounds 3 requires for `box-shadow` (each pixel within 5 percent of a true Gaussian). Evan Wallace's separable erf form (closed form along one axis, four samples along the other) is exact for rounded boxes and SHOULD be used; `1 - smoothstep(-blur, blur, d)` on the rounded-rect SDF is an acceptable approximation limited to `blur <= 8` logical pixels. Worldsim's first version put full strength at the edge and read as a hard band; the CSS-matched falloff is the one to keep.
- R5.13 A glow is a shadow with zero offset, a coloured shadow colour, and positive spread. No separate primitive.
- R5.14 Inset shadows are optional.

## 5.4 Circles, lines, polygons

- R5.15 Circles SHOULD be SDF discs with the same border modes, coverage formula, and quad inflation as rectangles, drawn as one quad. Worldsim tessellates a 64-segment fan and draws the border as 64 line quads at a different key, which is aliased, 65 draw groups, and its border loses its owner's key.
- R5.16 Lines are quads (two triangles) expanded to the line width on the CPU; the platform's native line primitive MUST NOT be used (WebGL caps it at one pixel and it does not anti-alias). An SDF capsule mode for anti-aliased lines with round caps is recommended.
- R5.17 Arbitrary polygons (tessellated vector art, gallery shapes) use `flat` mode with optional per-vertex colour. They are not anti-aliased by the shader; the implementation SHOULD add a feather ring on the CPU for the polygon and triangle components: one device pixel wide (`1 / ratio` logical), its outer vertices carrying the polygon colour with alpha 0 (premultiplied, so zero), its inner vertices the polygon colour, drawn in `flat` mode after the polygon; polygons that share edges MUST be feathered as one outline, not per triangle, or the shared edge shows a seam. Icons are distance-field atlas glyphs (chapter 12, R12.6), not polygons, in the baseline.

## 5.5 Images

- R5.18 An `image` draw is a quad with a texture, a source rectangle, and a tint colour (multiplied, so white is identity). Textures MUST be uploaded premultiplied (or premultiplied in the shader) so blending is correct at soft edges.
- R5.19 Nine-slice scaling SHOULD be supported for panel art: nine quads (or one instanced draw of nine) with fixed corner sizes, in one draw group.
- R5.20 Shape and text-free draws (`flat`, `rect`, `shadow`, `circle`) are texture-agnostic and never split a GPU submission. The implementation MUST bind a fixed set of resident textures to fixed units for the whole frame, at minimum the three font-role atlases, the icon atlas, and the UI art atlas (a `TEXTURE_2D_ARRAY` of art pages counts as one unit), and select per draw by a texture-slot index in a `switch` (dynamic sampler indexing is not permitted in GLSL ES 3.00, and WebGL2 guarantees sixteen units). A submission splits only when a draw references a texture that is not in the resident set and every dynamic unit is taken (`textureSlotsExhausted`, chapter 13, R13.13), never merely because consecutive draws use different resident textures. A list whose rows interleave an icon, a body label, and a mono value is therefore one GPU draw, not three per row.

## 5.6 Text

- R5.21 Glyphs are quads in `text` mode sampling a multi-channel signed distance field atlas; the atlas pixel range travels with the draw so several atlases with different ranges can share a flush. Details in chapter 6. Text MUST go through the same batcher and the same sort as shapes; a separate text pass was the first ordering bug worldsim ever recorded.

## 5.7 Alpha, blend modes, and colour

- R5.22 Blending is premultiplied `over`: source factor `ONE`, destination factor `ONE_MINUS_SRC_ALPHA`, for both colour and alpha. Colours are authored straight (as CSS) and MUST be premultiplied before blending, either on the CPU when packing vertices or as the last step of the fragment stage. Worldsim blends straight alpha; that works on an opaque native window and is wrong on a browser canvas, whose default compositing assumes premultiplied output, so a straight-alpha renderer leaves fringes and washed edges wherever the canvas shows the page beneath. On an opaque native target straight alpha is not wrong, only different: a native implementation MAY defer this rule until its UI is composited over another surface or shares shaders with a browser implementation, and scores it no until then.
- R5.22a Each draw carries a blend mode. `over` (default) and `additive` are free: `additive` is `over` with the output alpha forced to zero and no state change, so glows and particles behind cards need no barrier. `multiply` (`DST_COLOR, ONE_MINUS_SRC_ALPHA`) and `screen` (`ONE, ONE_MINUS_SRC_COLOR`) are per-group keys that split the GPU submission at that point in emit order without reordering, counted as `blendChange` (chapter 13, R13.13). Blend mode never affects sort order.
- R5.23 The final fragment output is the coverage-weighted premultiplied colour of R5.8 (for `rect` and `circle`), or `coverage * colourP * opacity` for the other modes, with `opacity` the inherited multiplier. Discard on coverage below 1/1024, never on colour alpha.
- R5.24 Colours are treated as sRGB display values and blended as-is (no linear-light conversion, no sRGB framebuffer). This is what CSS and every 2D UI toolkit do and what designers expect from the token values; linear blending makes anti-aliased dark text on light backgrounds look thin. An implementation MUST NOT enable sRGB framebuffer encoding for the UI pass.
- R5.25 The framebuffer alpha channel is meaningful only if the target composites over something. For an opaque window or an opaque canvas it can be ignored; screenshots MUST force alpha to opaque (chapter 13, R13.34).

## 5.8 Buffers and submission

- R5.26 Vertex, index, and instance storage on the CPU are typed, pre-sized, growable arrays reused across frames; zero per-frame allocation in steady state inside the batcher. The draw API's argument objects are the caller's and MAY be reused across frames (components SHOULD keep their style objects and pass them by reference); draw-list recording (chapter 2, R2.20) is development-only.
- R5.27 GPU storage for each stream is either a ring of at least `3 * flushesPerFrame` fixed-capacity buffers, or one buffer per stream of capacity at least three frames of data written at a monotonically advancing offset that wraps only when the region being overwritten is at least two frames old; either way one vertex array object per buffer (or per slot) is bound once per flush. Writing into a region the GPU may still be reading is prohibited. Respecifying the whole buffer every flush (orphaning) is a zero-fill on WebGL, not a discard, and is not used. A ring of three buffers rotated per flush is exhausted by a frame with three flushes, which a world plus a world-space UI plus the screen UI already is.
- R5.28 Per-flush uniform state is the projection, the target size, and the sampler slot bindings, in one uniform-block slot per flush (chapter 15, R15.15). Nothing is per draw. The device pixel ratio and the framebuffer height are not shader inputs (chapter 4, R4.4); the per-draw device-pixel constants the batcher needs (anti-aliasing footprint, feather width, shadow padding, distance-field range) are computed at submission. Every uniform MUST be initialised at program creation; worldsim had a uniform default to zero and render an entire pass (the baked entity pass, not the UI) invisible.
- R5.29 The context is created without a depth buffer, without multisampling, and without a stencil buffer unless chapter 4, R4.15 is implemented. The exact WebGL attributes are chapter 15, R15.2.

## 5.8a Resources

- R5.30 Textures and render targets are owned by a resource layer below the batcher with explicit `create` and `destroy` and reference counts; components hold handles only (chapter 2, R2.17); the null backend counts them.
- R5.31 Card and image art is packed at runtime into a `TEXTURE_2D_ARRAY` of 2048 or 4096 pages (`texStorage3D` with a full mip chain, `LINEAR_MIPMAP_LINEAR`) by a shelf packer; the array is one texture unit in the resident set of R5.20; art drawn below half size uses the mipmaps (the hand at 0.3 to 0.5 scale and deck lists at 0.15 are the common cases); entries are evicted least-recently-drawn when a residency budget (default 256 MB, configurable) is exceeded. UI atlases (fonts, icons, panel art) are built offline and never evicted.
- R5.32 Decoding uses the platform's off-thread decoder where available (`createImageBitmap` with `premultiplyAlpha: 'premultiply'` and `colorSpaceConversion: 'none'` in a browser); uploads are metered by a per-frame byte budget (default 2 MB) at `beginFrame`, oldest request first; a component whose texture is not yet resident draws its placeholder and re-renders when it becomes resident (chapter 12, R12.5). One 2048-square upload in a frame is a multi-millisecond hitch under ANGLE.
- R5.33 On context loss the resource layer re-decodes art from its source or from CPU copies it was told to keep; it MUST NOT keep CPU copies of art by default.
- R5.34 Off-screen targets (group opacity composites, chapter 3, R3.26; asset previews) are pooled by power-of-two size bucket, capped at a configurable count, and released when unused for a number of frames.
- R5.35 `bytesUploaded`, `residentTextureBytes`, `pendingUploads`, `evictions`, and `targetSwitches` join the counters of chapter 13.

## 5.9 Rationale

Worldsim moved from four line quads per bordered rectangle (20 vertices, no corner radius, corners overdrawn four times) to one SDF quad and recorded a five-times vertex reduction and corner radii for free; the shader cost is 15 to 20 ALU operations per pixel and does not register. Merging text into the same program removed the last shader switch and, with it, the last ordering hazard between text and shapes. The corrections here are the ones the graphics review found by working the pixel math: the border coverage formula (Zed's GPUI composites border over background and mixes by inner-edge coverage, the same result), the linear ramp and the inflated quad (Skia's practice), three-sigma shadow padding (Evan Wallace's shader), premultiplied gradient interpolation (CSS), the resident texture set (every batching renderer binds its atlases once), and the ring sizing that a multi-flush frame needs. The resource rules exist because for a card game the art dominates GPU memory and arrives over time; nothing in worldsim (vector art, no bitmaps) had to solve that.

## 5.10 Required tests and fixtures

- Visual fixture: rounded rects at radii 0, 4, 12, larger than half size, and per-corner; borders 1, 2, 6 px in each position mode; gradient fills including to transparent; a shadow at blur 0, 8, 24 with positive and negative spread; a glow; circles with borders; a 1 px and a 3 px line; a nine-sliced image; text over every one of them; the four blend modes over a photograph.
- Pixel tests (with a GPU, skip when headless): a 1 px opaque dark border on an opaque light fill, offset by half a device pixel, has no pixel in its outer edge row lighter than the border colour blended over the clear colour by its coverage (no halo); a border with alpha 0.5 over an opaque fill produces opaque output; a rect at x 10.25 has symmetric one-pixel ramps on its left and right edges; a `center` border is not clipped by the quad; premultiplied output over a transparent clear yields the expected RGBA; a `flat` triangle is opaque and identical across drivers; two abutting rects at a fractional x show no seam when snapped; a gradient from opaque red to transparent has no dark midpoint; a 24 px blur shadow shows no cutoff line.
- Batch tests (no GPU): a screen of mixed rects, circles, gradients, shadows, text in three roles, icons, and images from the UI atlas yields one draw group per call and one GPU draw per flush; a draw with a texture outside the resident set yields exactly one `textureSlotsExhausted` split; `multiply` yields one `blendChange` split; `additive` yields none; a frame with four flushes never writes a buffer region the previous frame may still read (assert on the ring bookkeeping).

## 5.11 Conformance checklist

| Item | Level |
|---|---|
| Single program, data-selected explicit modes including `flat` | required |
| SDF rounded rect with clamped radii, three border positions, RGBA border, exact coverage compositing | required |
| Linear one-pixel coverage ramp and quad inflation, no MSAA dependency | required |
| Box shadow as a preceding quad with CSS blur mapping, spread radii, and full padding | required |
| Premultiplied `over`, `additive` free, sRGB values blended as-is | required |
| Image quads with tint and source rect, premultiplied textures, resident texture set | required |
| Text in the same batcher and sort | required |
| 32-bit indices on the indexed path, reusable arrays, correctly sized buffer rings, per-flush uniform slots | required |
| Resource layer with ownership, metered uploads, context-loss recovery | required |
| Art texture array with mipmaps and residency budget | recommended |
| SDF circles and capsule lines | recommended |
| Per-corner radii, premultiplied gradients | recommended |
| Nine-slice, polygon feather | recommended |
| `multiply` and `screen` blend modes, inset shadows, per-side borders | optional |
